# v2 vs v10 横向对照(n=16 对,GLM-5.3-Flash 层,2026-10-31)

## 实验

两个规则版本**直接互相对照**(不是各自对无规则基线),同一基础 AGENTS.md 上只换文末规则段:
`test/scripts/ab/arm.mjs --arm v2|v10` 写入,v10 臂与部署态逐字节一致(diff 验证过)。
r1 v2 先、r2 v10 先,8 任务 × 2 臂 × 2 轮 = 32 派发,两臂 **16/16 全 PASS**,记录 `models` 全为 `GLM-5.3-Flash`。

数据 `results.v2v10.r{1,2}.{v2,v10}.jsonl`,存证 `runs.v2v10.r{1,2}.{v2,v10}/`。

实验插曲:第一遍 r1(MiniMax 层)跑到一半配额耗尽,用户要求重启,半程数据已归档
`data/ab/archive/*quota-aborted*`;重启后模型层切到 GLM,全程一致(两臂同层,可比)。
r2-t7-v2 一次派发文本打错一个字,当场作废重跑,未入数据集。

## 结果

| 指标 | v2 | v10 | Δ |
|---|---:|---:|---:|
| 总输出 | 15,409 | 14,218 | **−7.7%**(v10 更低,但配对均值 +13.4%、t=0.78 ns,7/16 更低) |
| 逐轮 | r1 6,794 / r2 8,615 | r1 6,013 / r2 8,205 | 两轮都 −5%~−12% |
| output 中位 | 966.5 | 817 | −15.5% |
| 请求数 | 54 | 56 | +3.7% |
| 强度 out/req | 285.4 | 253.9 | −11.0% |
| **思考字符** | 39,800 | 35,127 | **−11.7%** |
| 冲突权衡字符 | 6,541(16%) | 6,576(19%) | ≈持平(占比略升) |
| 工具参数字符 | 17,797 | 17,626 | −1.0% |
| 质量(PASS) | 16/16 | 16/16 | 零失败 |

配对差异 sd 69.2,单样本两头开花:t4/r1 v2=1,339 vs v10=252(−81%),t3/r2 v10=1,487 vs v2=607(+145%),
t8/r2 491→1,321(+169%),t1/r1 811→1,524(+88%)。方向(v10 更省)与幅度(−7.7%)都落在轮间噪声里。

## 结论

1. **GLM 层上 v10 比 v2 少 7.7% 输出**,且逐轮同向(r1 −11.5%、r2 −4.8%)、思考字符 −11.7%、
   中位 −15.5%——方向一致但配对 t=0.78 不显著,单样本方差(sd 69%)远大于效应。
2. **v2 的两个独有条款在这个方向上没有兑现**:「一次 Write 写全」没有造成整文件重写税(t2/t7 这类改文件任务
   v10 并未反超),「必跑一次检查」也没有让 v2 多省——v2 的请求反而更少一点。
   两个版本的冲突权衡体量相当,v2 没有出现历史上担心的额外权衡。
3. **综合跨层证据,维持 v10 的理由更充分了**:v10 在 GLM 对基线 −9.8%、对 v2 −7.7%(同向),
   对 v2 直接对照也占优;v2 唯一优势场景(qwen 层对基线 −12.0%)从未在与 v10 的直接对照中验证过。
   若未来要再压一档,值得试的是"v10 + v2 的一次性 Write 条款",但先例(v3/v8/v9)表明加条款容易引入反噬。
