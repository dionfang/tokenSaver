TokenSaver 部署使用说明

======================================================================
一、部署前提
======================================================================

1. Node.js ≥ 18 与 git。
2. 嵌入/精排模型二选一(默认 local):
   - local(推荐,无需外部服务):模型权重缓存在 code-index/hf-cache(约 439MB,
     复制部署需整目录带走;npm 安装缓存在 ~/.tokensaver/hf-cache),缺失时首次使用自动下载;
   - ollama:本机自行安装并启动 Ollama,再手工 pull(本工具不代拉、不自动启动):
       ollama pull qwen3-embedding:0.6b
       ollama pull sam860/qwen3-reranker:0.6b-F16
3. 动态模型路由(可选功能)仅 ZCode 与 Qoder 两个客户端支持,且要求自定义模型
   以 Anthropic Messages 协议接入(见三、配置说明)。

======================================================================
二、安装介绍
======================================================================

方式 A:源码仓直装(推荐)
  git clone https://gitcode.com/dionfang/TokenSaver.git
  cd TokenSaver/code-index
  node init.mjs --roots "D:/app-a,D:/app-b"
  数据写在 TokenSaver/data,不写入被索引的项目。

方式 B:复制部署
  把 code-index/ 整目录复制到目标项目(建议 scripts/code-index;hf-cache 必须带上,
  不带 node_modules 与 data/),在该目录执行:
  node init.mjs
  不传 --roots 时自动把当前项目(git 仓库根)列为索引目录;要额外索引其他目录才传
  --roots "其他路径"。数据落在旁边 data/(npm 安装固定 scripts/data/)。

方式 C:npm 安装
  npm i -D @dionfang/tokensaver
  npx tokensaver init --roots "D:/app-a,D:/app-b"
  数据固定写在仓库 scripts/data/。

安装参数:
  node init.mjs [--roots "路径1[,路径2]"] [--model-in ollama|local] [--hooks all|cursor|zcode|qoder]

  --roots     要索引的目录,逗号分隔;再次运行会合并新增目录;要删除目录,改 JSON 后重跑。
  --model-in  嵌入模型来源:ollama 或 local(默认)。
  --hooks     只装指定客户端的钩子。省耗记账功能三端都装;动态模型路由只装 ZCode 与 Qoder。

验证安装:node status.mjs(或 npx tokensaver status)
日常检索:node search.mjs 关键词 --k 5(或 npx tokensaver search 关键词 --k 5)

======================================================================
三、配置说明
======================================================================

配置文件有两处:

1) code-index/config.mjs —— 模型部署。data 里 JSON 的同名项对这里无效。
2) data/code-index.config.json —— 项目级配置(与 code-index/ 平级;未写的键用默认值)。

模型部署字段(改 config.mjs):
  models.embedding / models.reranker              ollama 模型名(默认 qwen3-embedding:0.6b、
                                                  sam860/qwen3-reranker:0.6b-F16)
  models.localEmbedding / models.localReranker    local 模型名
  ollamaBase                                      Ollama 地址(默认 http://localhost:11434)
  gpu                                             auto / cpu / gpu
  OLLAMA_KEEP_ALIVE / OLLAMA_NUM_CTX              Ollama 保活时长 / 上下文长度

项目级字段(data/code-index.config.json):
  roots               要索引的目录列表
  modelIn             ollama 或 local
  skipDirs            跳过的目录名(整表替换)
  exts                收录的扩展名
  jsonWhitelist       允许收录的 json 文件名
  maxFileBytes        单文件上限(默认 819200)
  readMaxLines        整文件 Read 行数上限(默认 500,设很大等于关闭拦截)
  chunk               分块参数(targetLines/maxLines/overlapLines/minTail)
  staleNonGitMs       非 git 目录重建间隔(默认 86400000 毫秒)
  knownAnnotations    "项目名/相对路径" → 一句职责说明

动态模型路由(可选;init 已自动生成 modelRouting 段,已有配置不会被覆盖):

  启用三步:
    ① init 已自动在 ZCode/Qoder 客户端播种 auto 虚拟模型;
    ② 会话里把模型切换到 auto,即对该会话启用;
    ③ 建议把 modelRouting.enabled 设为 true(只影响定档建议行,不影响路由本身)。

  接入要求:自定义模型必须以 Anthropic Messages 协议接入——
    ZCode:供应商类型选 anthropic-messages,baseUrl 指向供应商的 anthropic 网关;
    Qoder:条目 protocol 填 anthropic,baseUrl 指向 anthropic 兼容网关。

  modelRouting 可配置字段(data/code-index.config.json):
    enabled                    总开关(默认 false;只影响定档建议行,不影响路由)
    brandPriority              同档品牌的调用优先序
    providerPriority           同名模型挂多供应商时的取序
    providerOrder              宿主 UI 供应商拖动序(快照自动采集):同名供应商未进
                               providerPriority 时按它取序,冷却/配额尽按 UI 序逐个滑动
                               (Qoder 端无拖动序,按设置文件键序采集)
    retryOnRateLimit/maxRetries  上游失败时同轮换模型重试(默认 true/2)
    maxPhaseTurns              升档阶段最多持续的人类轮数(默认 4)
    switchGuard                上下文过厚时不升档(默认开,阈值 20 万 tokens;
                               同会话连拦 3 次自动放行,拦截时客户端会收到压缩建议)
    l2Shadow / l2              语义近邻投票开关与阈值
    decisionModel              自动打标签用的判定模型(enabled/model/providers/chunkSize)
    tierOptimize               自进化:自动学习定档参数(enabled 默认 false)
    blendNotice                auto 综合费率行注入开关(enabled 默认 true;关=只停
                               注入行,记账照常;仅路由宿主生效)

  综合费率(自动;modelRouting.blendNotice.enabled 默认 true):会话选 auto 后,每轮注入
  一行"auto 综合费率 ×N.NNN"——最近会话的实际花费 ÷ 同样 tokens 全走 R1 的花费
  (×1.0=纯 R1;每用一个高档轮倍率抬升;关开关只停注入,记账照常)。
  价格按四个难度档位计价(不按真实模型),来自 data/routing/model-prices.json 的
  tiers 段(每档 input/cacheRead/output 单价,元/M tokens;cacheWrite 可选,缺省按
  input 计;轮的档位由代理定档决定)。改价格直接编辑该 JSON,即时生效。

English

TokenSaver deployment guide

======================================================================
1. Prerequisites
======================================================================

1. Node.js >= 18 and git.
2. Embedding/reranker models, pick one (local by default):
   - local (recommended, no external service): weights cached in code-index/hf-cache
     (~439MB — copy the whole directory when copy-deploying; npm installs cache to
     ~/.tokensaver/hf-cache). Missing models download automatically on first use.
   - ollama: install and start Ollama yourself, then pull by hand (this tool never
     starts Ollama or pulls for you):
       ollama pull qwen3-embedding:0.6b
       ollama pull sam860/qwen3-reranker:0.6b-F16
3. Dynamic model routing (optional) supports ZCode and Qoder only, and requires
   custom models wired in via the Anthropic Messages protocol (see 3. Configuration).

======================================================================
2. Installation
======================================================================

Option A: install from the source repo (recommended)
  git clone https://gitcode.com/dionfang/TokenSaver.git
  cd TokenSaver/code-index
  node init.mjs --roots "D:/app-a,D:/app-b"
  Data is written to TokenSaver/data, not into your application repos.

Option B: copy deployment
  Copy the whole code-index/ directory into the target project (scripts/code-index
  suggested; include hf-cache, exclude node_modules and data/), then run there:
  node init.mjs
  Without --roots the current project (its git root) is indexed automatically; pass
  --roots "other/path" only to index additional directories. Data lands in a data/
  directory beside it (npm installs always use scripts/data/).

Option C: npm install
  npm i -D @dionfang/tokensaver
  npx tokensaver init --roots "D:/app-a,D:/app-b"
  Data is always written to the repo's scripts/data/.

init options:
  node init.mjs [--roots "path1[,path2]"] [--model-in ollama|local] [--hooks all|cursor|zcode|qoder]

  --roots     Directories to index, comma-separated; re-running merges new ones; to
              remove a directory, edit the JSON and re-run.
  --model-in  Embedding source: ollama or local (default).
  --hooks     Install hooks for the selected client only. The Token Ledger installs on
              all three clients; dynamic model routing on ZCode and Qoder only.

Verify: node status.mjs (or npx tokensaver status)
Daily search: node search.mjs keywords --k 5 (or npx tokensaver search keywords --k 5)

======================================================================
3. Configuration
======================================================================

Two config files:

1) code-index/config.mjs — model deployment. Same-named keys in the data JSON have
   no effect on this file.
2) data/code-index.config.json — project-level settings (beside code-index/; omitted
   keys use the defaults).

Model deployment fields (edit config.mjs):
  models.embedding / models.reranker              ollama model names
  models.localEmbedding / models.localReranker    local model names
  ollamaBase                                      Ollama URL (default http://localhost:11434)
  gpu                                             auto / cpu / gpu
  OLLAMA_KEEP_ALIVE / OLLAMA_NUM_CTX              Ollama keep-alive / context size

Project-level fields (data/code-index.config.json):
  roots               directories to index
  modelIn             ollama or local
  skipDirs            directories to skip (replaces the whole list)
  exts                file extensions to index
  jsonWhitelist       json filenames allowed into the index
  maxFileBytes        per-file size cap (default 819200)
  readMaxLines        full-file Read line cap (default 500; a huge value disables it)
  chunk               chunking parameters (targetLines/maxLines/overlapLines/minTail)
  staleNonGitMs       non-git rebuild interval (default 86400000 ms)
  knownAnnotations    "project/relative-path" → one-line description

Dynamic model routing (optional; init generates the modelRouting section, and an
existing config is never overwritten):

  Three steps to enable:
    (1) init already seeded the auto virtual model in ZCode/Qoder;
    (2) switch the session model to auto — routing is on for that session;
    (3) recommended: set modelRouting.enabled to true (only affects the tier line).

  Wiring requirement: custom models must use the Anthropic Messages protocol —
    ZCode: provider type anthropic-messages, baseUrl pointing at the provider's
    anthropic gateway;
    Qoder: entry protocol set to anthropic, baseUrl pointing at an anthropic-compatible
    gateway.

  modelRouting fields (data/code-index.config.json):
    enabled                    master switch (default false; only affects the tier line)
    brandPriority              brand call order within a tier
    providerPriority           ordering when one model spans several providers
    providerOrder              host UI provider drag order (auto-captured into the
                               snapshot): same-name providers not listed in
                               providerPriority follow it, and cooling/quota
                               exhaustion slides through them in UI order
                               (Qoder: settings-file key order)
    retryOnRateLimit/maxRetries  same-turn model retry on upstream failures (true/2)
    maxPhaseTurns              max human turns an upgrade phase lasts (default 4)
    switchGuard                no upgrades on very thick context (on by default,
                               threshold 200k tokens; auto-released after 3 consecutive
                               blocks; the client receives a compression suggestion)
    l2Shadow / l2              semantic neighbor voting switch and thresholds
    decisionModel              judge model for auto-labeling (enabled/model/providers/chunkSize)
    tierOptimize               self-evolution: learns tiering parameters automatically
                               (enabled default false)
    blendNotice                switch for the auto blended-rate line (enabled default
                               true; off = no line, accounting continues; routing
                               hosts only)

  Blended rate (automatic; modelRouting.blendNotice.enabled defaults to true): once a
  session selects auto, every turn carries a line "auto 综合费率 ×N.NNN" — the latest
  session's actual spend ÷ what the same tokens would cost entirely on R1 (×1.0 = pure
  R1; each high-tier turn bumps it up; the switch only stops the line, accounting
  continues). Prices are per difficulty tier (not per real model), from the tiers
  section of data/routing/model-prices.json (input/cacheRead/output per tier, CNY per
  M tokens; cacheWrite optional, defaults to input; a turn's tier comes from the
  proxy's tiering decision). Edit the JSON to change prices — effective immediately.
