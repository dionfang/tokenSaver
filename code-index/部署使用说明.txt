TokenSaver 部署使用说明

======================================================================
一、部署前提
======================================================================

1. Node.js ≥ 18 与 git。
2. 嵌入/精排/决策模型二选一(决策判定跟嵌入同路径;默认 local):
   - local(推荐,无需外部服务):模型权重缓存在 code-index/hf-cache(嵌入+精排+决策
     约 1.5GB(q4f16 决策 1.0GB+嵌入+精排;q8 权重已删,切回需重新获取——指标备档在 data/routing/profile-calibration-strands-q8.md),复制部署需整目录带走),
     缺失时首次使用自动下载;
   - ollama:本机自行安装并启动 Ollama,再手工 pull(本工具不代拉、不自动启动):
     版本推荐:**钉 Ollama 0.40.15**(实测嵌入批量 ~0.83s/块;0.40.16 退化至 1.17-1.42s/块约慢 1.5 倍,0.40.7 居中且波动大;三版本 /v1/systemone 决策端点均兼容)。升级前按同口径复测嵌入吞吐(batch 32、腾显存、90s 双采样)。
       ollama pull qwen3-embedding:0.6b
       ollama pull sam860/qwen3-reranker:0.6b-F16
       ollama pull tev1:0.8b(决策判定)
3. 动态模型路由(可选功能)仅 ZCode 与 Qoder 两个客户端支持;模型须以**自定义模型**
   接入(2026-11-24 起**不限接入协议**:Anthropic Messages / OpenAI Chat Completions /
   OpenAI Responses 三种均可;auto 激活段只同协议透传,跨协议桥接仅对显式模型保留,见三、配置说明)。

======================================================================
二、安装介绍
======================================================================

方式 A:源码仓直装(推荐)
  git clone https://gitcode.com/dionfang/TokenSaver.git
  cd TokenSaver/code-index
  node init.mjs --roots "D:/app-a,D:/app-b"
  数据写在 TokenSaver/data,不写入被索引的项目。

方式 B:复制部署
  把 code-index/ 整目录复制到目标项目(建议 scripts/code-index;hf-cache 必须带上,
  不带 node_modules 与 data/),在该目录执行:
  node init.mjs
  不传 --roots 时自动把当前项目(git 仓库根)列为索引目录;要额外索引其他目录才传
  --roots "其他路径"。数据落在旁边 data/。

安装参数:
  node init.mjs [--roots "路径1[,路径2]"] [--set-roots "路径1[,路径2]"] [--model-in ollama|local]
                [--hooks all|cursor|zcode|qoder] [--routing-on]

  --roots     要索引的目录,逗号分隔;再次运行会合并新增目录。
  --set-roots 逗号分隔目录**整表替换**(与 --roots 的合并语义相反;可重复传,传空=清空)。
              要删目录用它,或改 JSON 后重跑。
  --model-in  嵌入/决策判定模型来源:ollama 或 local(默认)。
  --hooks     只装指定客户端的钩子。省耗记账功能三端都装;动态模型路由只装 ZCode 与 Qoder。
  --routing-on 显式开路由记账闭环(写 modelRouting.enabled=true;向导完成步携带;
              已有配置人工改的 false 原样保留)。

验证安装:node status.mjs
日常检索:node search.mjs 关键词 --k 5

======================================================================
三、配置说明
======================================================================

配置文件有两处:

1) code-index/config.mjs —— 模型部署。data 里 JSON 的同名项对这里无效。
2) data/code-index.config.json —— 项目级配置(与 code-index/ 平级;未写的键用默认值)。

模型部署字段(改 config.mjs):
  models.embedding / models.reranker              ollama 模型名(默认 qwen3-embedding:0.6b、
                                                  sam860/qwen3-reranker:0.6b-F16)
  models.localEmbedding / models.localReranker    local 模型名
  models.decision / models.localDecision          本地决策判定模型(默认 tev1:0.8b /
                                                  strands:strands-decider-2B-hobson-v19:q4f16)
  ollamaBase                                      Ollama 地址(默认 http://localhost:11434)
  gpu                                             auto / cpu / gpu(注意:num_gpu 只对嵌入/精排
                                                  生效;ollama 路径的决策判定由 Ollama 自动放置、
                                                  local 路径为常驻 ONNX 进程,均忽略该选项)
  OLLAMA_KEEP_ALIVE / OLLAMA_NUM_CTX              Ollama 保活时长 / 上下文长度

项目级字段(data/code-index.config.json):
  roots               要索引的目录列表
  modelIn             ollama 或 local
  skipDirs            跳过的目录名(整表替换)
  exts                收录的扩展名
  jsonWhitelist       允许收录的 json 文件名
  maxFileBytes        单文件上限(默认 819200)
  readMaxLines        整文件 Read 行数上限(默认 300,设很大等于关闭拦截);
                    护栏面与索引面统一:只对 exts 白名单内类型拦截记账,
                    白名单外(图片/二进制/未收录)直接放行不计入节约口径
  chunk               分块参数(targetLines/maxLines/overlapLines/minTail)
  staleNonGitMs       非 git 目录重建间隔(默认 86400000 毫秒)
  knownAnnotations    "项目名/相对路径" → 一句职责说明

动态模型路由(可选;init 已自动生成 modelRouting 段,已有配置不会被覆盖):

  启用三步:
    ① init 已自动在 ZCode/Qoder 客户端播种 auto 虚拟模型;
    ② 会话里把模型切换到 auto,即对该会话启用;
    ③ modelRouting.enabled 新装默认已开(2026-11-20 裁定A;控制定档建议行/L1 分类/
       routing-log 三件事,不影响 auto 路由本身;人工改 false 原样保留)。

  接入要求与协议口径(2026-11-24):
    唯一硬要求 = 以**自定义模型**接入;供应商清单允许混合协议。自定义条目的 API 格式字段
    = 协议标签真源——
      ZCode:api.type(anthropic-messages / openai-chat-completions / openai-responses);
      Qoder:条目 protocol(anthropic / openai)。
    代理支持三种报文形态:Anthropic Messages / OpenAI Chat Completions / OpenAI Responses。
    **auto 连续激活段只允许同协议透传**(2026-11-24 用户定):只收协议标签明确包含
    入站协议的供应商,按品牌/档位正常排序;不转信封,上下文原样转发。首个干净成功的
    auto 请求以入站 adapter.name 正式建锁,auto 续接/工具轮/失败重试/证据升档均留在
    锁协议内;首轮选中模型不是锁真源。首次失败不建锁;显式模型请求立即结束当前 auto
    段并清锁,之后重新启用 auto 按当时入站协议建锁(不是整个会话终身锁),且首轮重新难度
    定档,不继承显式段留下的模型钉。
    同段内入口协议变化 → 本地 409(auto_protocol_locked),不打上游。锁仅在代理重启、
    显式模型请求或连续 24h 无活动时回收,进程内最多 1000 条,超量淘汰最旧。
    标签未声明/未知 → **不进 auto 池**。会话 ID 优先取请求体 session_id/metadata 或会话头
    (ZCode 用 x-session-id、Qoder 用无前缀 session-id);无稳定会话 ID 时才按 host+首条用户
    文本+系统提示归一回退,首轮材料完全相同的并发会话可能共用段锁。
    **显式模型保留跨协议桥接**:无损请求可转信封(路径/鉴权头/字段名/事件名按上游
    声明协议),系统提示/每轮消息/工具定义与参数/工具结果/模型输出不改一字。含 thinking
    块 / is_error 工具结果 / cache_control / 多模态块的请求不跨协议选型(退回同协议),
    绝不静默丢;跨协议+客户端流式时上游强制非流式,整包转换后合成 SSE。

  路由链粒度(2026-11-24):四档链的条目是 `模型@供应商`(钉死供应商)——
    同一模型挂多家时各家各自入链,次序按 providerPriority → 宿主 UI 拖动序(providerOrder);
    冷却/配额尽会自然滑到下一家的同名模型。

  modelRouting 可配置字段(data/code-index.config.json):
    enabled                    总开关(默认 true,2026-11-20 裁定A;控制定档建议行/L1
                               分类/routing-log 三件事,不影响 auto 路由本身)
    brandPriority              同档品牌的调用优先序
    modelTiers                 品牌三档默认表(2026-11-06 v4,v4.1 调档):normal=[deepseek,
                               glm,qwen,minimax]→R2 / mid=[kimi,grok,gemini]→R3 /
                               high=[claude,gpt]→R4;未识别品牌按 normal 兜底;pro/max 不特殊
    lightSuffixes              轻量版本后缀表(默认 flash,preview,coding,code,
                               coder,turbo,mini,air,nano,event,haiku,luna,lite,
                               base,sol,sonnet):命中即在品牌
                               默认档上降一档(R1 封底;flash 恒 R1)
    providerPriority           同名模型挂多供应商时的取序
    providerOrder              宿主 UI 供应商拖动序(快照自动采集):同名供应商未进
                               providerPriority 时按它取序,冷却/配额尽按 UI 序逐个滑动
                               (Qoder 端无拖动序,按设置文件键序采集)
    retryOnRateLimit/maxRetries  上游失败时同轮换模型重试(默认 true/2)
    maxPhaseTurns              升档阶段最多持续的人类轮数(默认 4)
    switchGuard                上下文过厚时不升档(默认开,阈值 20 万 tokens;
                               同会话连拦 3 次自动放行,拦截时客户端会收到压缩建议)
    l2                        **已回收(2026-11-14 用户裁定)**:L2 影子/实弹融合票恒开(代码常量,
                               shadow/live.enabled 配置键不再读取);阈值(minSim 0.55/minConf
                               0.6/live 0.3)属标定域走代码默认,旧阈值键(l2.minSim/minConf、
                               l2Live.minConf)标定域内一个版本窗口仍可读,不属用户配置面
    r3Lexical                 **已回收**:R3 词法通道与 P2 提前一拍恒开(代码常量,enabled/
                               eagerEscalate 不可配);词表本体在 tierClassify.mjs
    decisionModel              四票合议代签的判定模型(2026-11-09 v4 本地化收口:判定
                               恒本地、零远程调用——ollama=models.decision
                               (tev1:0.8b) / local=models.localDecision(Strands
                               ONNX q4f16),跟 modelIn 同路径;旧键 enabled/model/
                               providers/chunkSize/rRef 已废弃不读)。定档双臂与
                               代签门槛全部走模型判定档案 profiles(默认表:
                               tev1→arm1 0.6/all-r1、strands→0.5/ambiguous,
                               代签均 0.4/0.85,arm2 r3MinConf 0.85;未建档模型
                               回退 FALLBACK(0.75/ambiguous/0.6/0.9;arm1 恒影子 live=false)):臂1 按档案窗口
                               咨询词法 R1 轮(tev1=全部 R1、strands=置信≤0.5),
                               法官投到 R1 以上只按 R2 救回(一步一档,R3 留给臂2、
                               R4 恒不救);臂2 词法定档 R2 时现查,法官投 R3 过
                               r3MinConf 才救回 R3;判定失败维持原档(fail-open),
                               影子留痕 data/usage/r-ref-shadow.jsonl;判定模型
                               拉不起=决策票弃权)
    tierOptimize               自进化:自动学习定档参数(enabled 默认 false)
    blendNotice                auto 综合费率行注入开关(enabled 默认 true;关=只停
                               注入行,记账照常;仅路由宿主生效)

  综合费率(自动;modelRouting.blendNotice.enabled 默认 true):会话选 auto 后,每轮注入
  一行"[model-routing] auto 综合费率 ×N.NNN"——最近会话的实际花费 ÷ 同样 tokens 全走 R3 的花费(R3=1x 基准)
  (×1.0=纯 R1;每用一个高档轮倍率抬升;关开关只停注入,记账照常)。
  价格按四个难度档位计价(不按真实模型),来自 data/routing/model-prices.json 的
  tiers 段(每档 input/cacheRead/output 单价,元/M tokens;cacheWrite 可选,缺省按
  input 计;轮的档位由代理定档决定)。改价格直接编辑该 JSON,即时生效。

======================================================================
四、本地模型清理策略
======================================================================

本工具会拉起三类本地模型:嵌入、精排、决策判定(ollama 路径走 Ollama,local 路径走
transformers.js 常驻进程)。清理有两条触发线:

1) 切换模型后发起会话 → 卸掉"切换前拉起"的那几个
   会话开始时(auto.mjs)先算一次:当前配置不再需要的驻留模型一律卸掉(ollama 走
   keep_alive:0;local 路径则停掉装着旧模型的常驻进程,由预热按新配置重拉)。
   认的是"本工具拉起过的"——登记表 data/.warmed-registry.json(只增不减),用户自己
   pull 的聊天模型不碰。

2) 宿主关闭后 → 全部及时清理
   ZCode 的钩子只有七个事件、没有 SessionEnd,拿不到"宿主要走"的信号,因此会话开始
   时会拉一个脱离父进程的看护(cleanupWatch.mjs):祖先链上的进程全死、且本会话所属的
   宿主应用(ZCode/Cursor/Qoder)一个都不在了,就卸掉全部驻留模型并停常驻进程。
   多开窗口时模型是共享的:还有别的会话在用就不卸,等最后一个会话结束才统一清。

   看护日志:data/cleanup-watch.log;手动全清:node cleanup.mjs --all;
   只清"切换前拉起的":node cleanup.mjs --stale;查现状:node cleanup.mjs --status。

   看护按**进程表**去重(同一宿主只留一个还在值班的看护,失效的当场清退),不靠状态文件——
   状态文件在并发写时会丢条目,丢了就会每个会话再拉一个,实测堆积过 63 个看护/2.8GB 内存。

TokenSaver deployment guide

======================================================================
1. Prerequisites
======================================================================

1. Node.js >= 18 and git.
2. Embedding/reranker/decision models, pick one (decision judges on the same path;
   local by default):
   - local (recommended, no external service): weights cached in code-index/hf-cache
     (decision ONNX ≈1.0GB with q4f16 + embedding + reranker ≈1.5GB total; q8 weights removed — re-fetch if switching back, metrics archived in data/routing/profile-calibration-strands-q8.md — copy the whole directory when
     copy-deploying). Missing models
     download automatically on first use.
   - ollama: install and start Ollama yourself, then pull by hand (this tool never
     starts Ollama or pulls for you).
     Version pin: **Ollama 0.40.15** (measured bulk embedding ~0.83s/chunk; 0.40.16 regressed to 1.17-1.42s/chunk, ~1.5x slower; 0.40.7 in between with high variance; /v1/systemone decision endpoint compatible on all three). Re-benchmark with the same protocol (batch 32, free VRAM, 90s double-sampling) before upgrading.
       ollama pull qwen3-embedding:0.6b
       ollama pull sam860/qwen3-reranker:0.6b-F16
       ollama pull tev1:0.8b (decision judge)
3. Dynamic model routing (optional) supports ZCode and Qoder only; models must be
   wired in as **custom models** (since 2026-11-24 the wiring protocol is unrestricted:
   Anthropic Messages / OpenAI Chat Completions / OpenAI Responses all work;
   cross-protocol envelope bridging is retained for explicit-model requests, while a
   continuous auto segment is same-protocol pass-through only — see 3. Configuration).

======================================================================
2. Installation
======================================================================

Option A: install from the source repo (recommended)
  git clone https://gitcode.com/dionfang/TokenSaver.git
  cd TokenSaver/code-index
  node init.mjs --roots "D:/app-a,D:/app-b"
  Data is written to TokenSaver/data, not into your application repos.

Option B: copy deployment
  Copy the whole code-index/ directory into the target project (scripts/code-index
  suggested; include hf-cache, exclude node_modules and data/), then run there:
  node init.mjs
  Without --roots the current project (its git root) is indexed automatically; pass
  --roots "other/path" only to index additional directories. Data lands in a data/
  directory beside it.

init options:
  node init.mjs [--roots "path1[,path2]"] [--set-roots "path1[,path2]"] [--model-in ollama|local]
                [--hooks all|cursor|zcode|qoder] [--routing-on]

  --roots     Directories to index, comma-separated; re-running merges new ones.
  --set-roots Comma-separated directories that **replace the whole list** (opposite of
              --roots, which merges; repeatable; an empty value clears it). Use it to
              remove a directory, or edit the JSON and re-run.
  --model-in  Embedding / decision-judge model source: ollama or local (default).
  --hooks     Install hooks for the selected client only. The Token Ledger installs on
              all three clients; dynamic model routing on ZCode and Qoder only.
  --routing-on Explicitly enable the routing-accounting loop (writes
              modelRouting.enabled=true; carried by the wizard's finish step; a manual
              false in an existing config is preserved).

Verify: node status.mjs
Daily search: node search.mjs keywords --k 5

======================================================================
3. Configuration
======================================================================

Two config files:

1) code-index/config.mjs — model deployment. Same-named keys in the data JSON have
   no effect on this file.
2) data/code-index.config.json — project-level settings (beside code-index/; omitted
   keys use the defaults).

Model deployment fields (edit config.mjs):
  models.embedding / models.reranker              ollama model names
  models.localEmbedding / models.localReranker    local model names
  models.decision / models.localDecision          local decision-judge model names
                                                  (default tev1:0.8b /
                                                  strands:strands-decider-2B-hobson-v19:q4f16)
  ollamaBase                                      Ollama URL (default http://localhost:11434)
  gpu                                             auto / cpu / gpu (note: num_gpu only applies
                                                  to embedding/reranker; on the ollama path the
                                                  decision judge is placed automatically by
                                                  Ollama, and the local path runs a resident
                                                  ONNX process — both ignore this option)
  OLLAMA_KEEP_ALIVE / OLLAMA_NUM_CTX              Ollama keep-alive / context size

Project-level fields (data/code-index.config.json):
  roots               directories to index
  modelIn             ollama or local
  skipDirs            directories to skip (replaces the whole list)
  exts                file extensions to index
  jsonWhitelist       json filenames allowed into the index
  maxFileBytes        per-file size cap (default 819200)
  readMaxLines        full-file Read line cap (default 300; a huge value disables it);
                    guard scope equals index scope: only exts-whitelisted types
                    are intercepted/accounted, others pass through untallied
  chunk               chunking parameters (targetLines/maxLines/overlapLines/minTail)
  staleNonGitMs       non-git rebuild interval (default 86400000 ms)
  knownAnnotations    "project/relative-path" → one-line description

Dynamic model routing (optional; init generates the modelRouting section, and an
existing config is never overwritten):

  Three steps to enable:
    (1) init already seeded the auto virtual model in ZCode/Qoder;
    (2) switch the session model to auto — routing is on for that session;
    (3) modelRouting.enabled is already on by default for fresh installs (ruling A,
        2026-11-20; it gates the tier line, L1 classification and routing-log — auto
        routing itself is unaffected; a manual false is preserved).

  Wiring requirement and protocol semantics (2026-11-24):
    The only hard requirement is wiring in as a **custom model**; the provider inventory may
    mix protocols. The custom entry's API-format field is the protocol label source of truth —
      ZCode: api.type (anthropic-messages / openai-chat-completions / openai-responses);
      Qoder: entry protocol (anthropic / openai).
    The proxy supports three wire formats: Anthropic Messages, OpenAI Chat Completions and
    OpenAI Responses. **A continuous auto activation segment is same-protocol and
    pass-through only** (2026-11-24 ruling): only providers explicitly tagged with the inbound
    protocol enter its tier chain, ordered by brand/tier as usual; no envelope is rewritten and
    context is forwarded verbatim. The first clean auto success formally locks the segment to
    the inbound adapter.name; auto continuations, tool turns, failure retries and evidence
    upgrades stay inside that protocol. The first selected model is not the lock's source of
    truth. A first failure does not establish a lock. An explicit-model request immediately
    ends the current auto segment and clears its lock; re-enabling auto can establish a new
    lock from the then-current inbound protocol (not a lifetime session lock), and its first
    turn re-grades from scratch rather than inheriting the explicit segment's pinned model.
    An inbound-protocol change within the segment returns a local 409
    (auto_protocol_locked) without contacting an upstream. Locks are reclaimed on proxy restart,
    an explicit-model request, or 24h without activity; the in-process map holds at most 1,000
    entries and evicts the oldest on overflow.
    An undeclared/unknown label is **excluded from the auto pool**. The session ID is taken
    first from the body session_id/metadata or a session header (ZCode uses x-session-id,
    Qoder the unprefixed session-id); only without a stable session ID do host + first user
    text + system prompt provide a normalization fallback; concurrent sessions with identical
    first-turn material may share a segment lock.
    **Explicit-model requests retain cross-protocol envelope bridging**: lossless requests may
    be converted (path / auth headers / field names / event names follow the upstream's
    declared protocol), while system prompt, every message, tool definitions and arguments,
    tool results and model output remain verbatim. Requests with thinking blocks / is_error
    tool results / cache_control / multimodal blocks cannot select across protocols (the pool
    falls back to the same protocol); nothing is silently dropped. Cross-protocol + a streaming

======================================================================
4. Local model cleanup
======================================================================

This tool pulls up three kinds of local models: embedding, reranker, and the decision
judge (the ollama path runs them in Ollama; the local path runs them in a transformers.js
resident process). Cleanup has two triggers:

1) Starting a session after switching models — unload what the previous models pulled up
   At session start (auto.mjs) the tool recomputes what should stay resident and unloads
   the rest (ollama: keep_alive:0; local path: stop the resident process that still holds
   the old models, then warm again with the new config). Only models this tool pulled up
   are considered — tracked in data/.warmed-registry.json (append-only); your own chat
   models are never touched.

2) After the host closes — everything is released promptly
   ZCode's hooks expose seven events and no SessionEnd, so no callback can announce "the
   host is going away". Instead, a detached watcher (cleanupWatch.mjs) is started with
   the session: once every process on the ancestor chain is gone and the session's own
   host application (ZCode/Cursor/Qoder) is no longer running, it unloads every resident
   model and stops the resident process. With several windows open the models are
   shared, so nothing is unloaded while another session still needs them; the last
   session to end clears them all.

   Watcher log: data/cleanup-watch.log. Manual full cleanup: node cleanup.mjs --all;
   only the pre-switch leftovers: node cleanup.mjs --stale; current state:
   node cleanup.mjs --status.

   Watchers are deduplicated against the **process table** (one on-duty watcher per host;
   stale ones are cleared on sight) rather than against a state file — concurrent writes can
   drop state-file entries, and a dropped entry means one more watcher per session (63
   watchers / 2.8 GB were observed in practice).
